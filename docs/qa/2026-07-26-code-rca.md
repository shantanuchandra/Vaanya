# Code RCA — PAC evidence integrity

Date: 2026-07-26

Clinical acceptance boundary:
`docs/clinical/vaanaya-pac-source-of-truth.md`

## Fixed

### 1. New structured PAC fields disappeared in Supabase mode

- Symptom: OpenAI could produce a field proposal, but `save()` silently skipped
  it when the field did not already exist in `pac_field_proposals`.
- Root cause: the store implemented update-only persistence for proposals.
- Fix: insert new proposals, then persist their links to transcript segments.
- Guardrail: unit tests cover proposal insertion and source-link mapping.

### 2. Unclassified diarization speech was lost

- Symptom: a transcript turn with the application-supported `system` speaker
  role was discarded before persistence.
- Root cause: the database and write mapper only allowed clinician, patient and
  caregiver even though the contract also allows `system`.
- Fix: preserve all contract-valid roles and add a migration widening the check
  constraint.
- Source-of-truth impact: original utterances remain available even when
  diarization cannot safely assign a person.

### 3. Synthetic cases used an invalid persistence path

- Symptom: opening a synthetic case worked in connected mode, but saving it
  attempted to query its string ID against the numeric Supabase encounter ID.
- Root cause: reads came from a freshly generated in-code cohort while writes
  always went to Supabase.
- Fix: a stable in-memory demo store now owns both reads and writes for
  `synthetic-*` encounters.

### 4. Uploaded recordings reported zero critical gaps

- Symptom: an unprocessed upload showed `0 of 1 answered` and
  `0 critical gaps`.
- Root cause: the fallback applicable-field count was not included in the gap
  count.
- Fix: every required placeholder remains an explicit open gap until
  processing provides evidence.

### 5. Local database reset referenced a missing seed file

- Root cause: `supabase/config.toml` enabled `./seed.sql`, but the file did not
  exist.
- Fix: add an intentionally empty seed file; synthetic data remains outside the
  clinical database.

## Verification

- 87 automated tests pass: 39 API, 18 web, 5 contracts and 25 corpus checks.
- Type-check passes for API, web and contracts.
- Production builds pass.
- Internal-browser smoke test confirms uploaded recordings now show
  `1 critical gaps`.
- `supabase db lint --local` is pending because local Postgres is not running.
- The new migration must be applied to each deployed Supabase environment before
  enabling this write path there.

## Still pending by design

- The procedure-specific PAC category/checklist engine is not yet a validated
  clinical taxonomy. The current proposal counts are synthetic demo coverage,
  not a protocol. The participating anesthesiologist must validate the local
  paper-form categories and procedure modifiers before this becomes the signed
  completeness model.
- Multi-table transcript/proposal/source writes are not wrapped in one database
  transaction. A database RPC should make them atomic after the MVP demo.
- Supabase-backed patient search and encounter creation remain behind the
  longitudinal PAC migration; the buildathon cohort uses the demo store.
